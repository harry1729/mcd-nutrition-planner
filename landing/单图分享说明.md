# 单张分享图使用说明

## 结论：微信图片无法带链接，唯一可行方案是二维码

微信**不支持图片内嵌超链接**——发出去的图片只是图片，点任何地方都没反应。
这是平台限制，无技术手段绕过。

微信生态里让图片「能跳转到网址」只有一条路：**长按识别二维码**。

所以本图的设计目标变成：**让对方愿意长按那个二维码**。

---

## 成品

`png/star-card.png` — 750×2208（375宽 2倍高清，微信里不糊）

### 图的四层结构

| 层 | 内容 | 设计意图 |
|---|------|---------|
| 绿底标题 | 「20人订午餐 预算40块/人 到底点什么？」 | 用提问开场，让人代入自己的处境 |
| 白底结果 | 实测方案卡 + 107/158/45 三个数字 | 建立可信度 |
| 黄框指引 | 「长按下面的二维码 → 识别图中二维码 → 进项目页后点右上角 ☆ Star」 | **把操作说清楚**，对方知道下一步做什么 |
| 二维码区 | 大尺寸二维码 + 绿底「只要 3 秒」条 + 备用地址 | 提供可点击之外的第二条路 |

### 为什么二维码做到 260px

微信发图会压缩。小尺寸二维码在压缩后容易识别失败。
这里用 260px 显示 + H 级纠错（30% 容错），实测能被 OpenCV 正常解码。

---

## 发送方式

### 方式一：图片 + 文案（推荐）

发图，配文：

```
20人订午餐人均40 到底点什么？
写了个工具直接给能下单的清单，帮忙点个 Star ⭐

（长按图里二维码识别，或者点下面地址）
github.com/harry1729/mcd-nutrition-planner
```

微信会把文案里的地址识别成可点击卡片 —— 这是图片之外的第二条通道。

### 方式二：只发图

图里已经印了完整地址，对方长按二维码即可。适合发群里不配文的情况。

---

## 为什么图里还印了文字地址

三个原因：

1. **二维码识别失败时的兜底** —— 二维码被遮挡、屏幕太暗、微信压缩过度时仍可用
2. **对方会犹豫** —— 看到明确的地址会降低「这是不是钓鱼」的疑虑
3. **降低行动门槛** —— 知道只要去一个特定地方，不会在多个链接间挑

---

## 重新生成

改了文案或数据后：

```bash
cd landing
./export-star-card.sh
```

脚本做三件事：生成二维码 → 导出 PNG → **用 OpenCV 验证二维码能解码出正确 URL**。
最后一步是自检，改错地址会直接报错，不会让你发出去才发现扫不出来。

> 若卡片高度变化导致底部被裁切，脚本里的 `HEIGHT=1104` 需微调。

## 备选：多图版

`png/shot-a.png` ~ `shot-d.png` 是四图版（对比表、踩坑复盘各占一张），
适合发技术群或需要详细说明的场合。单图版信息密度更高，适合普通朋友。
