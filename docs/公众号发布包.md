### 开篇

上周三，行政问我：「20 人的会，午餐预算 800，人均不能超 40，
有两位同事不吃牛肉，能帮我看看点什么吗？」

我打开外卖软件，翻了 8 分钟。

麦当劳那页有 107 个餐品。有的写着「立省10.5元起」，有的看不出含不含牛肉，
有的配的是中薯有的配的是大薯。选到最后我算了一下，
最便宜的一套人均 19 块，但我不知道钠够不够、有没有人够吃。

**那天我意识到一个问题：这不是「选择困难」，是「缺少决策依据」。**

预算、份数、忌口、营养，这四件事各自都不难，难的是同时满足。

于是我想，能不能让 AI 把这件事算清楚？
——不是让模型拍脑袋推荐，而是让它按约束去求解。

### 为什么选团餐这个场景

我做了个统计：这届麦当劳程序员节大赛的 100 个参赛项目里，
做「省钱比价」的有 7 个进了前十，但**没有一个做营养合规**。

原因也合理——省钱最直观，最容易讲明白。

但真实的企业场景里，行政和HR 真正头疼的不是「能不能省 5 块」，
而是「会不会有人吃不了、会不会高钠高油被同事吐槽、份数够不够」。

所以我把它做成了**营养合规优先**：

在人均预算这个硬约束之下，同时要求蛋白质达标、钠不超标、避开忌口。

### 它算出来的东西

这是真实的运行结果（深圳某门店，20 人，人均预算 40）：

```
【推荐方案】
  · 芝士安格斯厚牛堡
    20 份 × ¥31.50 = ¥630.00

  合计 ¥630.00
  人均 ¥31.50

【营养估算】
  热量 约 696 kcal / 人
  蛋白质 32 g / 人
  钠 897 mg / 人

【MCP 计价复核】
  MCP 官方计价 ¥630.00
  本地估算   ¥630.00
  一致：与 MCP 计价一致
```

[图1：终端输出的真实方案截图]

注意最后那段「计价复核」——

**我没有自己算价格就算完了，而是把方案回传给麦当劳的官方计价接口再算一遍，
两边对上了才输出。** 这不是模拟数据，是真的调通了 MCP。

### 顺便说个反直觉的事

开发到一半时，我发现一个很反直觉的现象。

第一版的打分逻辑是「越省钱越好」，结果算法给我算出了这样的方案：

```
· 韩式烟熏芝士风味酱
  20 份 × ¥3.00 = ¥60.00     人均 ¥3 元
```

20 个人的午餐，一份酱料包。技术上这是「最优解」——预算没超、份数刚好、
营养也「达标」（因为营养数据没匹配上，按 0 算反而达标了）。

但业务上荒谬至极。

后来我把权重改了：**预算符合度只占 0.25，营养质量占 0.25**，
蛋白达标 0.20，钠控制 0.15，份数覆盖 0.15。

同样的预算下，它会优先选蛋白质更高、钠更低的组合。
比如人均 29 元但钠 1208mg 的方案，现在会被判为**风险项**直接落选。

**便宜，不等于能吃。** 这是我做这个项目最大的收获。

### 踩过的坑（我觉得这部分最有价值）

[图2：四个坑的整理图]

**坑 1：Token 少一个 `Bearer`，直接 403**

从控制台复制的 Token 直接粘进去，服务端返回 403「校验鉴权 authToken 必填」。
翻官方文档才发现要求是 `Authorization: Bearer <token>`——**少了 `Bearer ` 前缀**。

**坑 2：详情接口根本不返回价格**

`query-meal-detail` 只返回编码、名称、套餐结构和图片，**没有任何价格字段**。
我反复试参数，以为是自己传错了。

后来想明白了：价格本来就该用 `calculate-price` 算，因为价格含实时优惠，
不可能从静态商品详情里得出。

这个认知直接改变了架构——从「一个个查详情」改成「批量计价」，
107 个餐品分 9 批算完，还发现有些餐品原价 24 元、优惠后 15.9 元。

**坑 3：营养数据是纯文本，不是 JSON**

`list-nutrition-foods` 返回的是这样一坨：

```
中薯条,null,1210,289,4,12,38,165,18
巨无霸,null,2146,513,27,26,42,961,171
```

6000 多行的 CSV 风格文本，描述字段常为 `null`。
我刚写完 JSON 解析器才发现不对。最后按「末尾 7 个数字对齐」解析，
拿到 158 条营养数据。

**教训**：不要假设接口返回的一定是结构化数据。

**坑 4：求解器把 3 元酱料包选成 20 人主食**

就是前面那个。修法是给商品加「主食资格判定」——按菜单分类语义，
把酱料包、杯套、餐盘这些剔掉。

这四条我都写进了项目的复盘文档里。
**如果后面有人也要接麦当劳 MCP，能省不少时间。**

转化率会明显好于微信群发。
