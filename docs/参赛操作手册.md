## 一、MCP 认证：已解决，但需注意两处

### 1.1 你的配置原本差一个 `Bearer ` 前缀

原配置：
```json
"Authorization": "1yPT2kYRM6S2OtBWMfGrC1WTIkqCmvpJ"
```
服务端返回 `403 / 校验鉴权authToken必填`。

正确配置（已为你修正 `~/.workbuddy/mcp.json`）：
```json
"Authorization": "Bearer 1yPT2kYRM6S2OtBWMfGrC1WTIkqCmvpJ"
```

> 麦当劳 MCP 与其他服务不同，**必须带 `Bearer ` 前缀**。这一点在官方 README 的示例配置里是带前缀的，
> 但很多人从控制台复制 Token 直接粘贴就会漏掉。

### 1.2 WorkBuddy 侧需要「信任」自定义连接器

改完 `~/.workbuddy/mcp.json` 后，**新配置的 MCP 不会自动激活**：

1. 打开 WorkBuddy 的连接器管理页
2. 找到「自定义连接器」入口（右上角）
3. 对 `mcd-mcp` 点击**「信任」**
4. 之后即可在对话中直接调用麦当劳 MCP 工具

### 1.3 命令行使用需设环境变量

项目代码从环境变量读取 Token（不读配置文件，避免泄露）：

```bash
export MCD_MCP_TOKEN="1yPT2kYRM6S2OtBWMfGrC1WTIkqCmvpJ"
```

验证连通性：
```bash
cd mcd-catering-planner
node src/index.js --list-tools
```
应输出「麦当劳 MCP Server 当前提供 35 个工具」。

### 1.4 已验证可用的调用参数（省去你再踩坑）

| 工具 | 必填参数 | 备注 |
|------|---------|------|
| `query-nearby-stores` | `beType`、`searchType` | `searchType=2` 按位置搜；`1` 查收藏（个人账号通常为空） |
| `query-meals` | `storeCode`、`orderType`、`beType` | 返回分类与餐品**编码**，无价格 |
| `query-meal-detail` | `storeCode`、`orderType`、`beType`、`code` | **不返回价格** |
| `calculate-price` | `storeCode`、`orderType`、`beType` | 商品项用 `productCode`（不是 `code`），价格单位**分** |
| `list-nutrition-foods` | 无 | 返回**纯文本 CSV**，非 JSON |
| `query-meal-assistance` | `storeCode` | 固定 `beType=6`，需企业身份预置 |

## 二、仓库和 Issue：两个都要做，不冲突

这是两件独立的事，缺一不可：

```
你的 GitHub 仓库（放代码）          活动仓库（提交报名）
┌──────────────────────┐          ┌────────────────────────────┐
│ 你的用户名/mcd-catering-planner  │  M-China/                   │
│   ├─ README.md        │  ──────► │   mcd-developer-innovation-│
│   ├─ CONTEST_...md    │   发Issue  │   challenge  → New Issue  │
│   ├─ MCP_INTEGRATION  │          │                            │
│   └─ src/ ...         │          │  ★ 排名看这个仓库下你Issue │
└──────────────────────┘          │    登记项目的 Star 数        │
        ↑                          └────────────────────────────┘
   Star 也在这个仓库上刷
```

**规则原文依据**（`activityGuidelines.md`）：
- 「参赛者基于麦当劳 MCP 能力完成项目开发后，将项目发布至其在 GitHub 注册的个人账户中且可公开访问的 GitHub 仓库」→ **代码放自己仓库**
- 「参赛者应当于 2026年10月25日23:59 前，通过活动页面使用指定 Issue 模板提交参赛申请」→ **在活动仓库发 Issue**
- 「同一 GitHub 账号拥有多个参赛项目的，仅 Star 数最高的项目进入排行榜」→ **只做这一个项目**

### 2.1 第一步：建自己的公开仓库

1. 打开 <https://github.com/new>
2. Repository name：`mcd-catering-planner`
3. **Public**（必须公开，否则不满足报名条件）
4. ⚠️ **不要勾选** "Add a README file"（本地已有）
5. 点 Create repository

然后推送本地代码：

```bash
cd /Users/faithchen/WorkBuddy/社区活动/mcd-catering-planner
git remote add origin https://github.com/你的用户名/mcd-catering-planner.git
git push -u origin main
```

> **仓库创建时间检查**：现在创建是 2026-10-22，完全落在规则要求的
> 「2025年12月25日00:00 至 2026年10月25日23:59」窗口内。✅

### 2.2 第二步：在活动仓库发 Issue

1. 打开 <https://github.com/M-China/mcd-developer-innovation-challenge/issues/new>
2. 选择 Issue 模板（如果没有模板，创建一个含下述内容的 Issue）
3. **标题与正文之间不要有换行**——这是校验最容易踩的坑
4. 项目地址**不要用 Markdown 链接格式**（不要写成 `[名字](url)`）

正文内容（照抄，键和值写在同一行）：

```
【参赛申请】
项目名称：mcd-catering-planner 企业团餐决策助手
项目地址：https://github.com/你的用户名/mcd-catering-planner
项目简介：基于麦当劳 MCP 的企业会议餐决策助手，在预算、营养、过敏原、份数四重约束下用二维背包DP求解最优券分配，输出可下单方案并用 calculate-price 权威复核。
```

> 注意 `【参赛申请】` 后紧跟 `项目名称`，中间**不要空行**。
> 官方模板解析很严格，空行会导致校验失败。系统会回复成功或失败通知，失败会说明原因，可修改后重发。

### 2.3 第三步：导出 workbuddy.md（强烈建议）

WorkBuddy 专项奖励要求提交开发对话上下文。**本次对话就是完整的开发上下文**，
请将对话记录整理为 `workbuddy.md` 放入仓库根目录。

- 排行榜前 100 名 + 提交 workbuddy.md = **3000 积分**
- 前 3 名 = 10240 积分（无论是否用 WorkBuddy）

内容建议包含：需求分析、赛制调研、架构设计、关键 bug 修复过程、真实接口联调结论。
这些正是评委想看的「真实开发过程」证据。
