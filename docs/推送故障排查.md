# 推送故障排查与解决

> 记录 2026-10-22 实际遇到的推送失败，用于避免重复踩坑。

---

## 故障现象

终端执行后只出现一行报错：

```
cd: too many arguments
```

看起来像 `cd` 出错，实际是**三个问题叠加**。

---

## 问题一：三条命令被粘成一行（表层原因）

截图里的实际执行内容是：

```bash
cd /Users/faithchen/WorkBuddy/社区活动/mcd-catering-planner git remote add origin https://github.com/harrry1729/mcd-catering-planner.git git push -u origin main
```

`cd` 后面跟了 10 个参数 → `cd: too many arguments` → 立即失败。

更关键的是：命令用 `;` 串联而非 `&&`，所以 `cd` 失败后，**后续命令仍会继续执行**，
但此时工作目录还是家目录 `~`，那不是 Git 仓库，于是 `git remote add` 也失败了。

**症状**：终端滚屏后什么都没留下，很容易误判为"什么都没执行"。

**正确做法**：**一条一条执行，每条执行完确认结果**。或用 `&&` 串联（前一失败则后续不执行）：

```bash
cd /Users/faithchen/WorkBuddy/社区活动/mcd-catering-planner && git remote add origin <url> && git push -u origin main
```

## 问题二：GitHub 用户名拼写错误（关键原因）

| 项 | 拼写 | 是否存在 |
|---|------|---------|
| 钥匙串中存的账号 | `harry1729`（2 个 r） | ✅ 真实账号 |
| 当时使用的 URL | `harrry1729`（3 个 r） | ❌ 404 不存在 |

**查询方法**：

```bash
security find-internet-password -s github.com | grep acct
```

或直接看 <https://github.com/harry1729> 是否能打开。

> 你的 GitHub 主页 <https://github.com/harry1729> 已有 `mcd-catering-planner` 仓库（Public），
> 但 3 个 r 的路径是 404。

---

## 问题三：钥匙串凭据失效（最终阻塞点）

修正 URL 后推送，GitHub 返回：

```
remote: Invalid username or token. Password authentication is not supported for Git operations.
fatal: Authentication failed
```

**原因**：GitHub 自 2021 年起**彻底移除了账号密码推送支持**，只接受：
- Personal Access Token (PAT)
- SSH 密钥
- GitHub CLI 认证

你钥匙串里存的是旧版「用户名 + 密码」凭据，早已无效。
第一次推送失败后，git 还会把这条失效凭据从钥匙串清除，导致后续连用户名都查不到了。

**验证**：

```bash
security find-internet-password -s github.com | grep acct
# 无输出 = 凭据已被清除
```

## 解决方案

### 方案 A：Personal Access Token（最快，5 分钟）

1. 打开 <https://github.com/settings/tokens/new>
2. 填写：
   - **Note**：`mcd-contest-push`
   - **Expiration**：`90 days`（活动 10/25 截止，30 天足够）
   - **Scopes**：只勾 **✓ repo**（勾了它会自动包含 repo:status 等子项）
3. 点 **Generate token**
4. **立刻复制**这串 token（页面关闭后无法再看到）
5. 执行推送，粘贴 token 作为密码：

```bash
cd /Users/faithchen/WorkBuddy/社区活动/mcd-catering-planner
git push -u origin main
# Username: harry1729
# Password: <粘贴刚才的 token>
```

6. 凭据会自动存入钥匙串，之后不再询问。

> **安全提示**：token 等同于账号密码，不要贴进任何公开仓库、Issue 或聊天记录。
> 活动结束后到 Settings → Developer settings → Personal access tokens 把它删掉。

### 方案 B：GitHub CLI（推荐，一次授权长期有效）

```bash
brew install gh          # 若未安装
gh auth login            # 选 GitHub.com → HTTPS → 浏览器授权
gh auth setup-git        # 让 git 走 gh 的凭据
cd /Users/faithchen/WorkBuddy/社区活动/mcd-catering-planner
git push -u origin main
```

优点：不用手动管理 token 过期；`gh` 还能直接建仓、开 Issue，省去网页操作。

### 方案 C：SSH 密钥（一次性配置，最稳定）

```bash
ssh-keygen -t ed25519 -C "harry1729@github"   # 一路回车
cat ~/.ssh/id_ed25519.pub                     # 复制输出
```

粘贴到 <https://github.com/settings/keys> → New SSH key，然后：

```bash
cd /Users/faithchen/WorkBuddy/社区活动/mcd-catering-planner
git remote set-url origin git@github.com:harry1729/mcd-catering-planner.git
git push -u origin main
```

## 推送成功后的验证清单

```bash
# 1. 确认远程分支已建立
git branch -vv
# 应显示：* main dff6563 [origin/main] ...

# 2. 确认远程文件完整
git ls-tree -r --name-only origin/main | wc -l   # 应为 20

# 3. 浏览器打开确认
open https://github.com/harry1729/mcd-catering-planner
```

**网页侧必须逐项确认**：

| 检查项 | 要求 | 怎么验 |
|--------|------|--------|
| 仓库可见性 | **Public** | 仓库页右侧无 "Private" 标记；未登录状态能打开 |
| README 渲染 | 正常显示 | 仓库首页能看到 README 内容 |
| 文件齐全 | 20 个文件 | Files 标签页核对 |
| Token 未泄露 | 无 | 在仓库内搜 `Bearer` / `MCP_TOKEN`，应只见占位符 |
| 创建时间 | 2026-10-22 | 在合法窗口内 ✅ |

## 一页速查

```bash
# 逐条执行，每条确认结果
cd /Users/faithchen/WorkBuddy/社区活动/mcd-catering-planner
git remote -v                 # 确认：https://github.com/harry1729/mcd-catering-planner.git
git push -u origin main       # 推送
git branch -vv                # 验证：应显示 [origin/main]
```

**三个最容易出错的点**：
1. 命令粘成一行 → 用 `&&` 或逐条执行
2. 用户名多打一个 r → `harry1729` 不是 `harrry1729`
3. 用密码推送 → GitHub 已不支持，必须用 Token / gh / SSH
